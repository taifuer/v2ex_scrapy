# AI 编程工具使用体验：正文与评论试点

## 结论先行

这个专题值得做，但不适合直接做成“哪个工具最好”或“用户满意度指数”。正文与评论最有价值的补充，是解释**做什么任务、在什么条件下好用、哪里需要人介入，以及其他人如何补充或反驳**。

本轮完成可复现取样、文本覆盖审计和第一批证据核对。它是离线研究，不是新增的公开统计页面；没有向外部 AI 服务发送正文或评论，也没有生成自动情感分数。

## 样本与覆盖

数据截止 2026-08，候选范围 2021-01 至 2026-08。以下为 2026-09-05 本地快照的结果。

| 项目 | 结果 |
| --- | ---: |
| 标题规则召回的候选帖子 | 8,251 |
| 分层抽取帖子 | 200 |
| 样本发帖用户 | 195 |
| 单独补充的高互动案例 | 6 |
| 样本内、截止月份内的已存评论 | 3,057 |
| 样本帖子附言 | 25，其中 23 条时间不明 |
| 有非纯链接文字的正文 | 182 / 200 |
| 有非纯链接文字的评论 | 3,041 / 3,057 |
| 含图片或视频的评论 | 70 |
| 同帖内重复的规范化评论文本 | 22 |
| 已存评论数与回复数快照不一致的帖子 | 6 |
| 已逐项核对的证据 | 11 帖、16 处正文或评论 |

**200 帖尚未全部完成语义标注**。11 帖是用于建立分析维度的首批案例，不是对其余样本的替代，也不用于计算观点占比。

候选取自已有标题缓存，包括明确的编程工具名，以及带编程语境的模型名。规则排除了 MongoDB cursor、非编程场景的 Windows Copilot 等歧义，并排除推广、交易、赠送、招聘、拼车节点。其他节点中的自荐、教程、新闻或交易帖仍可能进入候选，需人工判断是否属于实际体验。

这不是 AI 编程讨论的完整召回：正文才提到工具的帖子、标题未包含相关表达的帖子不会自动进入；标题缓存也不是全文索引。工具别名清单见脚本中的 `TOOLS`。

抽样按季度、节点组和回复规模分为 118 层。节点组为脚本列明的程序员及 IDE 类节点与其他节点；回复规模为 0、1–19、20 及以上，未知值单列。每层至少一帖，其余名额按层规模平方根分配，保留抽取概率和设计权重。这样可覆盖早期、低回复和不同版面，但**原始样本比例不等于总体比例**。2026-Q3 只覆盖 7–8 月，不能当完整季度比较。

高收藏与高感谢各取候选前五作为补充，去重并排除已抽中的帖子后剩六帖；这些案例不计入随机样本分母。评论不设感谢门槛，按帖子读取全部已存楼层；不把同一帖或同一用户的多条回复当成独立受访者。

## 正文与评论带来的发现

### 1. “哪个更好”往往需要先问“用来做什么”

2022-12 的一个标题强烈偏好 ChatGPT，但评论将任务拆成代码解释、文档补写和 IDE 内补全，还有评论质疑两者是否获得了同等的上下文。它更适合表达为**任务与输入条件不同，工具比较会得到不同答案**，而不是依据主帖给两个产品打分。[帖子 #903712](https://www.v2ex.com/t/903712)，评论 #12485948、#12486290。

2026-01 的另一位用户没有完全迁移 IDE，而是保留 PhpStorm，在部分前端任务中搭配 Cursor。工具使用不是天然的单选题。[帖子 #1187117](https://www.v2ex.com/t/1187117)

### 2. 用户有时需要控制自动化，而不只是更快的生成

2022-03 一位作者肯定 Copilot 的能力，却希望只在按快捷键时触发，因为自动建议抢在自己的思考之前出现。这类需求同时包含认可和限制，简单正负面分类会丢失信息。[帖子 #843557](https://www.v2ex.com/t/843557)

该帖还有一条附言，补充了文档中的快捷键及作者的疑问；本地附言时间缺失，只保留为上下文，不据此判断后续问题是否解决。

### 3. “额度不够”的标题，可能包含对规则的误解

2024-09 的主帖担心 500 次用完，评论补充了快速额度与普通额度的区别。因此需要同时展示**作者的问题和评论中的澄清**，不能只统计“额度”或“用完”。这里只转述当时讨论，不核定当时或现在的官方套餐规则。[帖子 #1070514](https://www.v2ex.com/t/1070514)，评论 #15220238。

费用关切也不是新近才出现：2022-06 已有 Copilot 付费与替代工具的提问。当前案例只证明早期存在，不能据此宣布某一阶段的主流关注点。[帖子 #861257](https://www.v2ex.com/t/861257)

### 4. 首次生成与持续修改，是不同的问题

2026-08 的作者说最初生成效果不错，但新增需求后更容易与旧逻辑冲突；在评论建议后，作者反馈增加需求梳理环节有所帮助。**主帖、建议、作者后续反馈**连起来，才构成完整的案例。[帖子 #1232418](https://www.v2ex.com/t/1232418)，评论 #17944272。

2025-01 还有读取大型既有项目的需求，关注模块职责和交互，而非生成新代码。作者明确尚未使用 Cursor，因此只能记录为需求，不能记录为效果评价。[帖子 #1102906](https://www.v2ex.com/t/1102906)

### 5. 生成提速不等于审查成本降低

2026-02 的高互动案例讲述生成速度与自身理解速度之间的差距。另一篇高互动经验帖强调预先建立架构和规范，但其评论也明确反对盲信结果，要求人工审查及测试。合理的分析对象是**生成、理解、审查和返工之间的关系**，而不是将作者自报的效率倍数当作实测提升。[帖子 #1192730](https://www.v2ex.com/t/1192730)，[帖子 #1177039](https://www.v2ex.com/t/1177039)，评论 #17064847。

### 6. 最有用的评论，不一定有感谢；最长的评论，也不一定是本人经历

2023-07 一条零感谢回复具体说明了如何补充函数的使用上下文再请求修改。沿用热门评论的感谢阈值，会漏掉这样的操作细节。[帖子 #955742](https://www.v2ex.com/t/955742)，评论 #13337654。

相反，#1192730 中感谢较高的一条长评论包含文章翻译，不能把整段当作本评论者的亲身经历。#1168880 的主要论述则位于外部博客，本试点没有抓取该博客，不能用标题或评论倒推出其全文。[帖子 #1192730](https://www.v2ex.com/t/1192730)，评论 #17326014；[帖子 #1168880](https://www.v2ex.com/t/1168880)。

## 分析边界与下一步

“有文字”只说明技术上能读取，并不表示论述完整：样本中有 68 个正文包含外链，其中 3 个正文只有链接；图片内容没有 OCR。引用和代码标记在旧数据中可能已经丢失，自动识别的数量只是下限，仍需结合上下文审核。

六个回复数差异合计八条，可能涉及删除、快照不同步或抓取缺口，当前不判定原因。采集截止后新增的评论不计入；评论感谢、帖子收藏等仍是抓取时快照，不是历史事件时间序列。原始 `-1` 保持未知，不转换为零。

附言单独从 `topic_supplement` 按帖子索引读取。25 条中有 23 条本地时间无效，保留文字但不赋予推测日期、不参与阶段统计；明确晚于截止月份的附言不纳入。正文和附言也是当前存档，不代表某个历史时点的原文版本。后续扩大语义分析前，应先处理附言时间记录的质量问题。

建议下一步只围绕本专题完成以下工作，不扩展到全站自动语义分析：

1. 对 200 帖标注是否属于实际体验，区分求助、本人经历、教程、产品展示、转载与无关候选；保留排除理由。
2. 在明确的任务和工具上下文中，标注收益、限制、应对方法，并逐条链接证据；评论中的质疑和作者后续反馈单独保留。
3. 对模糊、反讽、转载案例安排第二次人工复核。标注规则稳定前，不做情绪百分比或工具排名。
4. 只有有效体验样本足够时，才比较年度或阶段的主题分布；同时报告样本数、取样权重和未能判断的比例。

未来展示更适合一页专题：任务类型、使用中的约束、应对方式，以及可回溯的讨论案例。先呈现上述有证据的差异，不急于做新的综合指数。

## 复现与文件

```bash
.venv/bin/python scripts/sample_ai_coding_study.py \
  --start 2021-01 --end 2026-08 --sample-size 200 --seed 20260905 \
  --review analysis/studies/ai_coding_review.json
.venv/bin/python -m unittest discover -s tests -p 'test_ai_coding_study.py'
```

- `scripts/sample_ai_coding_study.py`：候选提取、确定性分层取样、逐帖正文评论审计、证据校验。
- `analysis/studies/ai_coding_review.json`：八个初步分析维度与已核对的短证据；这是研究记录，不是自动分类词表。
- `analysis/data_audits/ai-coding-study/`：忽略提交的候选清单、样本、独立案例、覆盖报告及校验结果。完整正文和评论不进入前端 `public/` 或部署包。

脚本只扫描已有的轻量标题缓存，命中后读取帖子元数据，选中后通过主键及 `ix_comment_topic_id` 读取正文和评论；不扫描整张评论表，也不重建分词。每个线程保存内容摘要哈希，审核文件独立保存，重新取样不覆盖人工证据。校验会检查帖子与评论归属以及原文是否仍包含引用；原文匹配只能证明引文存在，不能证明解释正确。
