# V2EX Dashboard 技术架构与功能实现

本文说明从 V2EX 页面到静态看板的完整数据链路。指标口径和当前分析结果见 [数据分析说明](DATA_ANALYSIS.md)，关键取舍和踩坑记录见 [项目复盘](PROJECT_RETROSPECTIVE.md)。

## 1. 系统概览

```text
V2EX 页面
   |
Scrapy + 页面解析
   |
v2ex.sqlite 事实库
   |
analysis/build_analytics.py
   |-- analysis/analytics.sqlite
   `-- analysis/v2ex-analysis/public/dynamic-*.json
                                      |
                              Vue 3 + Vite + ECharts
                                      |
                              Nginx + Docker 静态部署
```

原始数据库超过 GB 级，浏览器不直接读取 SQLite，也不执行全量聚合。Python 离线构建器先完成清洗、统计和分片，前端只加载当前视图需要的静态 JSON。

## 2. 抓取与事实存储

- `v2ex_scrapy/spiders/` 包含帖子、节点和成员爬虫，`CommonSpider.py` 承载共用请求与错误处理。
- `v2ex_parser.py` 负责页面解析，`DB.py` 定义帖子、评论和成员模型，`pipelines.py` 负责批量写入、回滚和关闭时刷新。
- `config.py` 从环境变量和仓库外文件读取 Cookie、代理和并发配置；敏感信息不进入 Git。
- 帖子抓取支持有界 ID 区间、离散 ID、强制刷新和评论分页补抓。“已有记录”不等于“数据完整”，会继续检查标题、节点及页面回复数。
- 删除、权限受限和失败记录保留可追踪状态。交互值 `-1` 表示未知或不可用，不应被解释为真实的零。
- `scripts/backfill_missing_topics.py` 扫描 ID 缺口和空标题/空节点等质量问题，适合在大范围抓取后做定向补全。

## 3. 离线分析管线

`analysis/build_analytics.py` 是分析产物的唯一入口，当前数据契约为 schema v20。它负责：

1. 过滤 1970 年等无效时间，统一时区，计算最近完整月和年度累计口径。
2. 构建全局、月度、年度、话题、内容、节点、成员、互动和生命周期指标。
3. 将聚合中间结果写入忽略的 `analysis/analytics.sqlite`，将前端契约写入 `public/dynamic-*.json`。
4. 在 `dynamic-manifest.json` 记录 schema、源数据指纹、组件生成时间、文件名和字节数。

`--if-changed` 会比较帖子内容、互动、评论、成员和完整月指纹。源数据未变时直接跳过；只有评论或成员变化时可复用帖子相关产物；帖子或 schema 变化时重建其依赖项。这是组件级增量构建，不是把新周期 Top N 简单合并进旧榜单。

## 4. 话题、内容与分词

### 4.1 话题分析

“话题”专指 V2EX 帖子的原始标签。`tag_synonyms.json` 合并同义写法，`tag_stopwords.json` 排除无意义标签；逐期 Top、连续趋势、详情对比和关联话题都基于这一结构化信号。话题代表帖子会先限定当前话题，再按自然年保留综合互动 Top 10，不使用全站榜单作为前置候选；月度 Top 3 另存为 128 个延迟加载分片，仅在用户选择趋势时间点时读取。`topic_groups.json` 使用若干原始话题和节点精确匹配组织话题板块，不读取标题分词；各板块可以重叠，不是互斥分类。

### 4.2 标题内容分析

“内容”指帖子标题中出现的领域词，用于补充标签未覆盖的产品名、事件和新概念。`analysis/content_hotspots.py` 的处理顺序为：

1. 清理 URL 和邮箱，通过分段正则忽略其他无效符号，并保护已知中英文领域词。
2. 使用 jieba 精确模式分词，`content_user_dict.txt` 提供产品、公司、模型和技术名称。
3. 通过 `content_synonyms.json` 统一大小写、缩写和变体，再用 `content_stopwords.txt` 排除论坛标题常见泛词。
4. 过滤纯数字、过短/过长词和无效符号；同一标题内的同一词只计一次。
5. 按“包含该词的帖子数”排名，同时保留作者数、节点覆盖、周期趋势、关联话题/内容和代表帖子。

分词结果缓存在忽略的 `analysis/content_tokens.sqlite`。缓存按帖子 ID 和标题维护，词典、同义词或停用词变化会更新处理指纹，只重算新增、标题改变或配置失效的记录。`content_hotspot_audit.py` 会检查头部作者/节点集中度和示例标题，分词词表修改前应先审计语境，而不是只看词频。

`content_groups.json` 将热词组织为内容板块。它与话题板块分开：前者依赖标题词，后者依赖原始标签。当前不分析正文和评论语义，也不将简单关键词匹配包装为情感或经济指数。

## 5. 功能与信息架构

| 主板块 | 主要功能 | 回答的问题 |
| --- | --- | --- |
| 概览 | 全局趋势、月度数据、年度数据、帖子/成员/互动变化 | 社区规模和结构如何变化 |
| 帖子 | 话题演变与详情、内容演变与详情、节点结构与详情、生命周期 | 讨论什么、在哪里讨论、如何扩散 |
| 成员 | 成员演变、有限活跃成员详情、发帖/评论/感谢排名 | 谁在持续参与，其参与结构如何 |
| 互动 | 热门帖子、热门评论、排序与分页 | 哪些内容获得更多浏览、收藏、感谢或回复 |
| 观察 | 构建时生成的离线点评、数据证据与相关详情入口 | 哪些跨板块变化值得解读 |

话题、内容和详情趋势支持最多 5 个对象对比，关联数据始终以主对象为准。全局搜索只覆盖已聚合的话题、内容、节点和有限成员，不是 V2EX 全文搜索；空输入候选由离线构建的最近 12 个完整月份 Top 3 话题和 Top 3 内容组成，并在两类之间按名称去重。

## 6. 静态数据契约与加载

- **时间分片**：趋势和内容热点按年拆分，月度/年度排名按周期单独输出。
- **索引与详情分离**：选择器先读名称和数量索引，选中实体后再读详情。
- **稳定哈希分片**：话题、内容、节点、成员和成员评论使用 SHA-1 映射到 64 个桶，一次详情查询只加载一片。
- **按视图加载**：Vue 视图和 ECharts 运行时通过动态 `import()` 拆分，打开对应页面时才下载。
- **版本缓存**：`dataClient.ts` 使用 manifest 版本为动态 JSON 加查询参数；Vite 对 JS/CSS 生成内容哈希文件名。
- **URL 状态**：顶层板块、子视图、时间范围、主实体、对比项、排序和页码可恢复；所有参数经过枚举、范围、长度或实体白名单校验。

## 7. 前端实现

前端位于 `analysis/v2ex-analysis/`，使用 Vue 3、TypeScript 和 Vite。ECharts 统一实现折线图、热力图、图例、缩放和悬停高亮，`chartTheme.ts` 管理全局配色，`chartLayout.ts` 管理桌面端/移动端布局。排名栏、周期选择、搜索选择、对比、分页、导航和加载状态均抽成可复用组件，避免同类视图各自实现。

移动端不只压缩尺寸：导航、指标卡片、筛选器、搜索弹层、图表横向滚动和 footer 都有独立断点与触控测试。

## 8. 验证与部署

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
.venv/bin/python analysis/build_analytics.py --if-changed
.venv/bin/python scripts/validate_analytics.py
cd analysis/v2ex-analysis
npm run build
npm run test:budget
npm run test:e2e
```

Python 单测覆盖解析、配置、抓取范围、写入和聚合辅助函数；validator 检查 schema、索引引用、数量约束和 manifest 文件大小；构建预算限制 JS、CSS 和最大 JSON 分片；Playwright/Axe 覆盖桌面端、移动端、URL 恢复、按需加载、图表交互、分页、搜索滚动和严重级无障碍问题。

生产使用 Docker 中的 Nginx 托管 `dist/`，开启 Gzip，对带哈希的前端资源使用长期 immutable 缓存，对动态 JSON 使用短缓存和 manifest 版本。容器只绑定本机端口，由宿主机反向代理对外服务。线上统计脚本属于服务器专用配置，不进入仓库。

## 9. 扩展原则

1. 新增指标前先定义事实、时间语义、分母、异常值和最小样本。
2. 大规模转换放在离线构建器，浏览器只处理范围组合和展示状态。
3. JSON 契约变化时同步提升 schema，更新 validator、TypeScript 类型和 E2E。
4. 分词词典、同义词、停用词和聚合板块必须通过示例标题人工审计，不凭 Top 排名直接决定。
5. 新页面应先说清它回答的问题。若只是重复既有搜索、趋势或详情，应扩展现有视图而不是新增 Tab。
