# V2EX 看板路线图

路线图只保留尚未验证的工作。新增功能必须先说明问题、数据口径、缺失值和验收方式；已完成事项归档到 [项目复盘](PROJECT_RETROSPECTIVE.md)。

## P0：持续质量治理

- 扩充真实标题金标和高风险歧义样例，不以机器输出或低价值样例凑数量。
- 每次数据更新后复核新增候选、覆盖率、作者/节点集中度和代表标题，防止词表随时间漂移。
- 继续跟踪不可访问帖子、未知互动值和评论快照差异；只把可复现的异常提升为发布门禁。
- 核对附言时间的解析与历史记录：AI 编程试点样本的 25 条附言中，23 条缺少有效时间；未恢复前只作上下文，不参与阶段统计。

## P1：按瓶颈演进构建器

- 通过构建阶段耗时判断是否需要脏周期、脏实体级增量更新；没有明确收益时维持当前组件级重建。
- 数据契约增长时优先拆分索引、详情和时间分片，并用请求数、字节数与首屏耗时验收。

## P2：需先建立标注集

- 标题意图分类：求助、经验、分享、招聘、交易等。
- 正文或评论语义分析：[AI 编程工具使用体验试点](AI_CODING_STUDY.md) 已完成 200 帖取样与首批证据核对；下一步完成相关性及体验标注、复核歧义，再决定是否公开展示。不要将案例数量或关键词命中率当作观点占比。

## 非目标

不做简单关键词匹配包装出的情绪或经济指数、全站词云、自动生成的大规模 AI 点评、全量成员画像，以及没有明确性能收益的前端框架重写。
