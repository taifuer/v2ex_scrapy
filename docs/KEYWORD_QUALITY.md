### 本轮修复

- 补充婚恋家庭、健康身心以及居住、保障类明确词汇；不降低普通词的 20 个标题、15 位作者、3 个节点门槛，不强制进入逐期 Top 排名。
- 原始话题按现有板块重点词机制补入，仍使用独立话题数据，不从标题推造帖子标签。
- 高频话题保留前 500 个，再补充达到门槛的板块重点话题，不再用固定总额让彩礼等议题挤掉 Steam、vim、Xcode 等已有话题。
- 女朋友与女友、男朋友与男友、谈恋爱与恋爱、燃油车与油车按同义表达去重。婚姻、婚礼、彩礼、结婚保持独立，抑郁与抑郁症也不互相替代。
- 关键词详情的关联话题沿用主话题库的规范名称，修复 Git/git、offer/Offer 等大小写不一致造成的关联遗漏，同一帖子仍只计一次。
- 保留跑步机、焦虑症、前女友等复合词，防止新词把更具体的设备、病名和关系状态截成宽泛词；不达展示门槛的词仅保留正确分词，不输出详情。
- 拦截“部分手游”误命中分手、“机房租用”误命中房租、“买车票”误命中买车、“宠物业”误命中物业。
- “对象”不再独立触发情感与家庭分类。对象存储、Java 对象不会仅凭该标签进入家庭板块；原始数据不删除。
- `exchange` 是物物交换，不再作为投资节点；工程节点使用实际的 `js`、`go`、`db`，经济节点使用 `eco`，情感节点依据本地官方中文名称快照校正。

### 不自动放宽的情况

- 睡眠包含设备睡眠，退休包含设备退役，烂尾包含软件项目和影视作品，伴侣包含软件与硬件产品。暂不凭这些词将帖子归入健康、养老、住房或婚恋，不新增全局停用规则。
- 嫁妆、备孕等标题样本尚未达到普通词门槛，不因同属婚育就降低要求。话题与关键词可能因各自实际数量不同而只收录其中一类。
- 彩礼等词可能受到事件讨论带动；焦虑等词也可能出现在求职、产品或书籍标题中。关键词数量表示标题提及，不能解释为婚育态度、患病率或社区情绪指数。
- 既有词表中，“恒生”混有银行与公司名，“芒果”混有水果与视频平台，“期权”混有招聘薪酬与投资交易。暂不删除或强制归一；后续应抽样区分明确实体和语境，再决定是否增加独立细分词。

### 本地重建结果

本轮关键词详情从 704 个增加到 770 个，净增 66 个，原有关键词没有被移除。话题从 500 个调整为 615 个，采用高频基础名单加重点补充项；“对象”不再作为婚恋重点词补入，其余原有话题保留。关键词板块新增“婚恋与家庭”和“健康与身心”。

修复后彩礼、婚礼、婚姻、公积金分别命中 138、137、137、609 个标题；月嫂、学区房、异地恋分别为 32、36、25 个。标题按词边界及同义归一统计，因此修复前后数量可能变化，并非原始帖子被增删。关键词缓存只重新处理 14,936 个受影响标题，原始帖文内容未改动。

## 后续复核方式

先看原始标题、作者与节点覆盖，再决定是否补词、修复边界或合并写法。稳定词未进入逐期 Top 30，不代表不能有搜索和详情；高频也不代表必然有分析价值。歧义词不能只凭字符串包含关系归类。

每次变更先运行：

```bash
.venv/bin/python scripts/evaluate_title_keywords.py
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
.venv/bin/python analysis/build_analytics.py --if-changed
.venv/bin/python scripts/validate_analytics.py
```

继续审计可使用 `scripts/audit_title_keyword_candidates.py --skip-cache-sync`。该报告只列候选，不自动修改词表；低频领域词还需定向核对，不能只检查全局最高频的前几百个词。真实标题回归样本保存在 `analysis/title_keyword_gold.jsonl`，分类反例同时由单元测试覆盖。
